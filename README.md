# Experimental Sensor Data Validation Pipeline

A reproducible batch ETL portfolio prototype for simulated temperature, pressure, and voltage. It **does not** use real industrial sensor data, and its thresholds/risk scores are illustrative rather than medically or industrially validated.

## Architecture

Synthetic readings → field/type and physical-range checks → normal/abnormal/invalid categorization → transparent rule-based risk score → CSV + SQLite → SQL quality counts.

Invalid rows are kept for inspection with **NULL risk scores**; they are not silently discarded or treated as low risk. Valid values outside normal operational bands receive a simple score of 30 per abnormal signal (capped at 100). This is a **heuristic**, not an ML model or calibrated probability.

## Setup and run

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
python pipeline.py --n 1000 --seed 42
python -m unittest discover -s tests -v
```

The demo seed produces 1,000 readings: 833 normal, 164 abnormal, and 3 invalid.

- `output/processed.csv` contains the latest batch.
- `output/readings.sqlite` retains distinct batches. The CLI hashes the processed CSV bytes and records that batch ID in the same database transaction as the readings. Replaying identical output leaves the row count unchanged. A changed batch can include readings that overlap with earlier batches.
- Existing SQLite files keep their rows. Runs made before batch tracking have no recorded batch IDs.

Example SQL:

```sql
SELECT status, COUNT(*) AS n FROM readings GROUP BY status;
SELECT sensor_id, COUNT(*) AS issues
FROM readings WHERE status <> 'normal' GROUP BY sensor_id ORDER BY issues DESC;
```

## Important design decisions and limitations

- Deterministic synthetic data via NumPy generator seed.
- Physically plausible (illustrative) limits: temperature -20 to 100 °C, pressure 80 to 120 (arbitrary pressure units), voltage 0 to 5 V. Normal bands: 15–35 °C, 95–105 pressure units, 3–4.2 V.
- These bands are invented demonstration values: revise for an identified sensor and proper domain units before any real deployment.
- SQLite persists results locally; **PostgreSQL integration is not implemented** in this deliverable.
- Batch replay protection applies to SQLite. The CSV is a separate export and can be regenerated by rerunning the command.
- Potential master's-level next step: statistical drift monitoring, ground-truth event labels, precision/recall for anomaly detection, false-positive analysis, parameter sensitivity, and run-level data quality metrics.
